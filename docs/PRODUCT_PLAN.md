## 1. 執行摘要

QTrans 要讓 Minecraft 模組包的任務與腳本文字本地化工作更容易開始、可中斷續做、可檢查及可交付。使用者選擇模組包 ZIP 後，工具協助建立專案、掃描可翻譯文字、使用所選翻譯方式產生翻譯、保護格式與程式碼，再輸出翻譯後的 ZIP 及覆寫檔案。

產品以離線優先的桌面工作流程為核心：模組包分析、專案狀態、術語及翻譯記錄在本機處理；只有使用者啟動翻譯時，文字才會送到其選擇的外部翻譯服務。是否增加雲端帳號、集中式翻譯或付費服務，不屬於本企畫書預設範圍，須另行決策。

首發不以「支援所有模組包」為目標，而是先明確界定並驗證 Windows 支援範圍、可安全回寫的檔案類型及已測試的翻譯服務。正式上市前要補齊品牌資產、安裝與解除安裝體驗、資料安全說明、可靠更新機制、測試樣本及使用者文件。

### 2.2 使用者要完成的工作

1. 選擇來源模組包並知道哪些檔案會被處理。
2. 預覽掃描結果，確認文字數量、檔案種類及跳過理由。
3. 選擇翻譯服務與目標語言，設定術語和必要選項。
4. 了解資料是否會離開本機、哪些文字會送往哪個服務。
5. 執行、暫停或中斷流程；再次開啟時可判斷是否能安全續做。
6. 檢查成功、失敗、未翻譯及格式警告，必要時修訂翻譯。
7. 產生可辨識的輸出 ZIP／overrides，並可確認輸出與來源的差異。

## 3. 產品願景、定位與原則

### 3.1 願景

讓模組包作者、翻譯者與玩家能以可理解、可驗證且可復原的流程，製作及分享 Minecraft 模組包的繁體中文內容。

### 3.2 定位

QTrans 是專注於 Minecraft 模組包任務與相關玩家可見文字的本機桌面翻譯工作台，不是通用翻譯網站，也不是自動修改所有模組程式碼的工具。

### 3.3 產品原則

- **安全預設：** 原始 ZIP 保持不變；只回寫明確支援且可定位的文字。
- **結果可追蹤：** 顯示掃描數量、翻譯狀態、錯誤與產出路徑。
- **不偽裝成功：** 部分失敗、placeholder 遺失、封裝錯誤等均須明確呈現。
- **本機優先：** 專案資料留在使用者選擇或應用程式管理的本機位置；外送翻譯須告知服務對象。
- **逐步揭露複雜度：** 新手可走精簡流程；進階使用者能管理供應商、術語、覆寫及專案選項。
- **格式保守：** 不確定文字用途或語法時寧可跳過並說明，不猜測後破壞檔案。
- **能力透明：** 文件及介面區分已支援、實驗性、未支援與未驗證項目。

## 4. 目標使用者與使用情境

### 4.1 主要使用者

| 使用者 | 需求 | 產品重點 |
|---|---|---|
| 模組包玩家／新手翻譯者 | 快速取得可安裝的繁體中文輸出，不熟悉 CLI | 導引式工作流程、預設設定、清晰錯誤及不需手動管理服務 |
| 模組包作者／維護者 | 批次處理內容、保護原格式、重複更新翻譯 | 可重現流程、增量翻譯、差異檢視、CLI 與可設定輸出 |
| 社群翻譯者 | 維護固定譯名、檢查未翻譯內容、協作交付 | 術語表、翻譯匯入／匯出格式、品質檢查與來源脈絡 |
| 進階使用者 | 使用自架或相容翻譯模型、調整工作參數 | provider 設定、端點、模型、快取及可診斷日誌 |

### 4.2 核心情境

- 全新使用者選擇 ZIP，接受引導後完成掃描、翻譯、檢查與輸出。
- 使用者只想掃描及匯出待翻譯清單，不呼叫外部服務。
- API 額度或網路中斷時，使用者保留進度，稍後可重試失敗項目。
- 維護者更新模組包版本後，以既有術語和翻譯記錄處理新舊差異。
- 使用者只需要 overrides，而非重新封裝完整 ZIP。
- 使用者在安裝、啟動或更新失敗時，能查明原因並保留專案資料。

## 5. 首發範圍與非目標

### 5.1 首發建議範圍（Windows）

- Windows x64 桌面 GUI、CLI、隨附本機 Go 翻譯服務及使用者級安裝程式。
- 從使用者選擇的 ZIP 建立隔離專案；不得覆寫來源 ZIP。
- 對經測試的 FTB Quests 與 KubeJS 檔案形式提供掃描、翻譯、檢查及輸出。
- Google 公開翻譯端點、OpenAI 相容 API、DeepL、offline glossary 和測試 mock 的能力與限制明確標示；mock 不出現在一般使用者的建議流程。
- `zh_tw` 作為首發預設目標語言；至少定義語系代碼正規化及輸出檔名規則。
- 專案清單、最近開啟、失敗重試、翻譯檢視／匯出和輸出開啟能力，按里程碑實作。
- 安裝、升級、解除安裝、保留或移除使用者資料的流程有可測試規則。

### 5.2 暫不列入首發承諾

- macOS、Linux 原生 GUI 或跨平台安裝器。
- 支援任意 Minecraft 檔案、所有模組、任意 JavaScript 語法或未知任務序列化格式。
- 自動修改 `.jar`、二進位資產、模組程式碼或伺服器執行檔。
- 雲端帳號、線上專案同步、集中式翻譯記憶庫、社群市集或付費 SaaS。
- 保證任何第三方翻譯服務持續可用、免費或符合所有商業用途。
- 未經明確產品決策前，提供自帶模型下載或遠端模型託管。

上述項目可在後續評估，不代表永久排除。

| PRJ-01 | P0 | 可用檔案選擇器選擇 ZIP；無效、損毀、無權限或不支援的輸入須顯示可操作錯誤。 |
| PRJ-02 | P0 | 建立專案時保留來源路徑及來源指紋；不同內容的同名 ZIP 不得共用專案狀態。 |

### 6.4 目標語言與介面本地化

- 首發先完成繁體中文 UI 與 `zh_tw` 任務輸出的一致性。
- 內部資料模型分開存放 UI locale 與 translation target locale，不能用一個設定值混用兩種語意。
- 語言代碼需經正規化、驗證並映射至各 provider 所需代碼；不支援的語言在開始工作前提示。
- UI 字串集中管理；日期、數字、字體、文字換行、長字串及混合中英文均納入版面測試。
- P1 加入英文 UI；後續依維護能力與社群需求決定其他 UI 語言。
- 目標語言擴充採 provider × target 支援矩陣；需測試輸出路徑、Minecraft 語系代碼慣例及 fallback 行為。

### 6.5 GUI 與易用性

| ID | 優先級 | 規格與驗收條件 |
|---|---|---|
| UX-01 | P0 | 首次啟動能完成選檔、掃描、設定翻譯、執行、檢查結果及開啟輸出的完整導引；不要求使用者先讀 CLI 文件。 |
| UX-02 | P0 | 所有長任務在背景執行；UI 可回應並顯示階段、進度、取消／停止能力及可預期的完成狀態。 |
| UX-03 | P0 | 失敗訊息包含發生階段、原因、可採取動作及相關日誌；不得僅顯示「失敗」或成功樣式。 |
| UX-04 | P0 | 視窗縮放、最小尺寸、窄寬度、高 DPI、長路徑、長翻譯及大量日誌均有人工或自動化驗收。 |
| UX-05 | P1 | 新手模式只顯示必要選項；進階模式才展示 provider 細節、批次、覆寫、快取及路徑等參數。 |
| UX-06 | P1 | 重要操作（重新翻譯、刪除資料、覆寫輸出、清理快取）在執行前說明影響並提供明確確認。 |

### 6.6 輸出與交付

- 完整 ZIP 與 overrides 分別顯示用途、路徑及檔案數。
- 產出前檢查輸出路徑、磁碟空間及來源／目的檔案是否衝突；預設不覆寫來源。
- 打包後重新讀取 ZIP，驗證可開啟、必要 entry 存在、翻譯檔案符合目標語言代碼。
- 提供輸出差異摘要、未翻譯數、失敗數與輸出驗證結果。
- 提供專案報告匯出；報告預設不得包含 API key、完整敏感路徑或未經使用者同意的私人文字。

## 7. 品牌與視覺識別提案

### 7.1 品牌目標

呈現「可靠的本機工具、Minecraft 社群語境、翻譯工作台」；避免直接複製 Minecraft、Mojang、Microsoft 或第三方模組的標誌、方塊紋理及商標識別，並避免讓使用者誤以為官方產品。

### 7.2 必交付品牌資產

- 原創主標誌與單色版本；向量主檔 SVG。
- Windows 應用程式圖示 `.ico`，至少包含 16、24、32、48、64、128、256 px 常用尺寸。
- 安裝器、解除安裝項目、桌面捷徑、視窗及工作列統一圖示。
- README／GitHub 社群預覽圖及簡短品牌使用規範。
- 若後續建立網站，再另定網站、社群圖片與文件視覺，不將其列為首發阻擋項。

### 7.3 視覺方向提案

可探索「任務卷軸／書頁＋對話或翻譯符號＋像素化幾何」的原創圖形。圖形需在 16 px 仍可辨識，不能依賴小字、細線或複雜場景。色彩要與 GUI 現有深色介面協調，同時測試淺色背景、單色列印與色覺差異。

品牌方向、名稱、標誌草案與色彩需先經使用者確認，再整合至 GUI 和安裝器；此處是設計任務規格，不是已核准的最終視覺。

## 8. 技術架構與品質要求

### 8.1 架構責任

- **qtrans-core（Rust）：** ZIP 專案、檔案掃描、格式解析、回寫、驗證及封裝；不依賴 GUI。
- **qtrans-cli（Rust）：** 可重現、可自動化的核心工作流程及結構化退出狀態；GUI 以受控方式呼叫。
- **qtrans-gui（Rust／GPUI）：** 使用者體驗、專案設定、進度與錯誤呈現；不重做核心解析及回寫。
- **translator（Go）：** provider adapter、批次、重試、placeholder、快取及 loopback HTTP API；不任意對外開放服務。
- **封裝／更新：** 安裝器、版本資訊、校驗、更新通知與使用者資料生命週期；版本來源須一致。

架構調整需服務明確需求；不為抽象而抽象。CLI 與 GUI 共用的資料格式、錯誤型別及版本協定需有相容性測試。

### 8.2 安全與隱私

- 預設服務只綁定 loopback；非 loopback 綁定位址須明確警告及保護。
- 驗證 HTTP request 大小、批次量、字串長度與並行上限，並設連線及處理 timeout。
- 不記錄金鑰、Authorization header 或完整翻譯文字；診斷 log 預設採遮蔽或摘要。
- 儲存 provider secret 前，必須先決定 Windows Credential Manager／DPAPI 等 OS 安全儲存方案；未決定前只使用明確的工作階段輸入方式。
- ZIP 解壓限制路徑穿越、symlink 逃逸、重複路徑、資源耗盡及不可信檔案名稱。
- 更新檔只接受官方 repository 發布來源，限制大小，驗證 checksum，並評估程式碼簽章；checksum 本身不能取代簽章信任鏈。
- 整理第三方 Rust／Go 依賴的授權與版本更新流程；不得承諾未完成的安全審核。
- 提供隱私說明，列出本機儲存位置、外送欄位、provider、快取期限／清除方式及錯誤回報的資料內容。

### 8.3 可靠性與效能

- 核心操作可重複執行，來源 ZIP 不變；寫檔採暫存檔與原子替換，避免中斷破壞專案。
- 背景工作有明確生命週期：啟動、執行、取消、逾時、重試、程序結束與關閉 GUI。
- 對大 ZIP、長字串、海量任務、慢服務、429、斷網、磁碟不足及權限錯誤建立測試。
- UI 不因掃描、翻譯、網路、檔案操作或子程序等待而凍結。
- 性能目標以固定測試硬體及測試模組包建立基線後訂定；未測量前不宣稱具體處理速度。

### 8.4 測試與品質閘門

- Rust：format、workspace tests、Clippy；核心解析器與 ZIP 操作須有負向測試及回歸 fixtures。
- Go：gofmt、tests、vet；HTTP API 使用 httptest 與 fake providers，不呼叫付費／公開實際翻譯 API。
- GUI：可測試的狀態流程與畫面操作檢查；至少覆蓋首次執行、取消、重試、錯誤、輸出及窄視窗。
- Release：從乾淨 runner 建置；核對版本、安裝檔、checksum、安裝／升級／解除安裝及資料保留。
- Release blocker 不得以「本機可執行」代替乾淨環境驗證；CI 必須可重現並保留必要測試結果。

## 9. 發行、支援與商業化

### 9.1 發行策略

- 首發 Windows x64；使用 GitHub Releases 提供版本說明、安裝程式、SHA-256、支援範圍及已知問題。
- 每個 Release 附上版本、建置來源 commit、支援平台、變更摘要、升級注意事項及資料保留說明。
- 自動更新只負責發現及下載候選版本；安裝前由使用者確認。失敗時保留現有版本，避免破壞性半安裝。
- 正式對一般使用者公開下載前，至少完成一次候選版本（RC）安裝與回退演練。
- 建立版本支援政策：最新穩定版的回報方式、修補優先級及停止支援舊版的通知方式。

### 9.2 授權與營運模式（待決策）

目前 repository README 標示 MIT。是否維持純開源免費、接受捐款、提供社群贊助，或日後建立付費服務，需另行決定。任何商業模式都不得暗示使用者已擁有第三方翻譯服務額度；Google、OpenAI 相容服務與 DeepL 的費用、條款及可用性由各服務提供者決定，QTrans 需提供清楚告知。

### 9.3 支援入口

- GitHub Issues 提供 bug 回報模板、環境版本及不含敏感資料的診斷摘要。
- 文件說明如何產生可重現測例；不要求上傳完整模組包或私有翻譯內容。

- 是否加入匿名使用統計、崩潰上報或外部客服工具，均須另行取得明確產品決策與使用者同意。

### 10.1 首發前 Go／No-Go

**Go 條件：**

- P0 功能及安全驗收均通過。
- 支援矩陣、已知限制、資料流及第三方服務責任公開說明。
- 安裝、更新、解除安裝及使用者資料處理已在乾淨 Windows 環境驗證。
- 代表性模組包能產生有效輸出；翻譯失敗及跳過項目不會隱藏。
- Logo、視窗與安裝器圖示已完成使用者核准及整合。
- Release 產物可校驗，版本與來源 commit 可追溯。

**No-Go 條件：**

- 會修改來源 ZIP，或已知可造成任務／腳本破損而沒有保護措施。
- API 金鑰會寫入不安全位置或出現在 log。
- 主要流程仍會凍結、靜默失敗或將部分失敗回報成功。
- 安裝更新可能覆蓋／刪除使用者資料而未告知。
- 供應商資料傳輸及已知格式限制沒有向使用者說明。

## 11. 成功指標

首發前建立基線，再設定數值目標；不得先捏造達標數據。

| 指標 | 定義／觀測方式 |
|---|---|

## 12. 主要風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 遊戲／模組版本與檔案格式差異 | 漏掃或錯誤回寫 | 支援矩陣、版本化 fixtures、保守跳過及清楚提示 |
| 公開翻譯端點限流、變更或條款調整 | 工作中斷或服務不可用 | provider 狀態說明、重試與續跑、可替換 adapter，不承諾第三方 SLA |
| LLM／機翻改寫 placeholder 或語意 | 遊戲格式損壞、品質不佳 | placeholder 驗證、失敗隔離、人工校訂及 provider 測試集 |
| 大型 ZIP 或惡意壓縮檔 | 記憶體／磁碟耗盡或路徑穿越 | 解壓限制、路徑正規化、容量上限及安全測試 |
| GPUI／Windows 特定相容問題 | GUI 無法啟動或顯示異常 | 固定支援環境、乾淨 VM／runner 測試、備份與診斷流程 |
| 自動更新供應鏈風險 | 執行不可信安裝檔 | 官方來源 allowlist、雜湊、評估程式碼簽章、使用者確認與回退方案 |
| 商標或第三方資產侵權 | 品牌及發行風險 | 原創 Logo；核查字體、圖示、依賴授權及 Minecraft 相關商標使用 |
| 功能面無限制擴張 | 延遲首發且難維護 | 以 Windows 首發和 P0 閘門限制範圍；其他平台與格式依需求證據排程 |
| 未授權的資料蒐集 | 隱私及信任受損 | 首發不預設遙測；任何外送或統計需透明告知、最小化並取得明確同意 |
