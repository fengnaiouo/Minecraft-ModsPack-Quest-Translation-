# AI 協作對話結論

本文件只保留對後續開發有用的需求、決策與工作界線，不存放逐字聊天、私人資料或未經核對的技術結論。內容來源限於本 repository 及本次提供的 QTrans 對話摘要。

## 已確認的使用者需求

- 專案目標是 Minecraft modpack 任務漢化；核心處理 FTB Quests 與 KubeJS。
- 技術方向為 Rust 核心／GUI、Go 翻譯服務，GUI 使用 GPUI。
- GUI 需要能適應視窗尺寸；若單頁無法清楚呈現功能，應採用明確導覽，而不是持續把功能堆在同一頁。
- AI 文件必須是 QTrans 專案自己的文件，並包含有用的專案脈絡，例如歷程、討論結論、決策與 Git 說明。
- 要求對 UI、功能、安裝與解除安裝做整體健檢，找出不合理或高風險處並修正；解除安裝不得無提示刪除使用者資料。
- 要求所有 Markdown 文件同步更新，但排除 Skills 目錄內容。
- 要求 repository 呈現公開專案應有的樣貌，具備完整授權、貢獻、安全、範本與 CI 文件。

## 已確認的協作界線

- 任務操作及資料來源限於 QTrans repository；不得讀取 repository 外的 Skills、共用 Markdown、個人設定或其他本機資料。
- `.agents/skills/` 是此專案自己的 Skills。不要把它們當成外部共用文件，也不要在未獲要求時重寫 Skill 正文。
- 嚴格遵循使用者指定的檔案範圍。只要求 Markdown 時，不修改 Rust、Go、PowerShell、設定或其他非 Markdown 檔案；也不執行會順帶改寫它們的命令。
- 保留工作區既有變更與使用者資料；未明確要求時不還原、不清理、不建立 commit。
- 先前未經確認的 GUI 導覽修改已撤回；除非使用者再次確認，不把側欄方案當成已採用設計。

## 需要重新確認的事項

- GUI 導覽與自適應的最終版面。
- 「全部修復／模組化」的具體範圍及完成標準。
- 發布、commit 或會影響使用者資料的操作。

## 更新規則

只在對話中出現新的明確需求或決策時更新；將提案、已確認決策及已完成實作分開描述。不得把推測寫成使用者原話或已交付功能。
