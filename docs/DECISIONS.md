# 專案決策紀錄

本檔記錄目前可確認的產品與協作決策。程式已實作的行為仍須以程式碼和測試核對；未完成的設計不視為已核准。

## D-001：翻譯工具的技術方向

- **狀態：** 已確認為專案目標
- **決策：** 以 Rust 建立核心與桌面 GUI，翻譯服務使用 Go；GUI 採用 GPUI。
- **依據：** 使用者對 QTrans 的初始需求；目前 repository 也包含 Rust workspace 與 `go/translator`。

## D-002：模組包處理範圍

- **狀態：** 已確認為產品目標
- **決策：** 以 Minecraft modpack ZIP 為輸入，處理 FTB Quests 與 KubeJS 玩家可見文字並產生繁體中文翻譯。
- **依據：** 使用者需求及目前 README 專案說明。
- **注意：** 精確支援的檔案形式與路徑以核心程式和測試為準，不因目標描述而假設所有格式都支援。

## D-003：GUI 操作方式

- **狀態：** 方向已確認，具體版面待確認
- **決策：** GUI 須自適應；若完整自適應單頁造成內容擁擠，應提供清楚的功能導覽，不應將所有功能堆在同一頁。
- **限制：** 未經使用者確認不得自行選定或恢復側欄方案。先前提出的側欄變更已撤回。

## D-004：AI 文件的資料邊界

- **狀態：** 已確認
- **決策：** QTrans 的 AI 指引、專案歷程、協作結論及 Git 文件應存在本 repository，並以本 repository 與使用者提供的需求為依據。
- **決策：** `.agents/skills/` 為專案自有 Skills；不讀取 repository 外的 Skills 或共用 Markdown，也不擅自改寫 Skill 正文。
- **決策：** 使用者限定只改 Markdown 時，不得觸碰程式碼、設定或產生檔案。

## D-005：提交與發布

- **狀態：** 已被 D-006、D-007 取代
- **決策：** 沒有使用者明確要求時，不建立 commit、不 push、不建立 tag 或發布版本。
- **依據：** 本專案代理指引及 GitHub workflow；workflow 的自動發布條件仍以實際設定為準。

## D-006：驗證後自動提交與推送

- **日期：** 2026-11-09
- **狀態：** 使用者已確認
- **決策：** 對本專案的變更，在相符的驗證通過後，自動建立 commit 並推送到目前已設定的 GitHub remote；Git 操作優先使用 `rtk git`。
- **範圍：** 僅推送本次工作所需且已驗證的變更，不納入不相關或既有未提交檔案。
- **依據：** 使用者已授權本專案 GitHub 管理權限，並明確要求自動推送。

## D-007：完整 GitHub 專案及發布管理

- **日期：** 2026-11-09
- **狀態：** 使用者已確認
- **決策：** 使用者授權完整管理本專案 GitHub repository，包括 commit、push、建立 tag、GitHub Release 及正式發布；達到發布驗收條件後可自行執行，不需再次詢問。
- **發布閘門：** 發布前核對目標 commit、版本/tag 一致、必要測試、Windows 安裝包、checksum 與發行說明；發布後確認 Actions 與 Release 附件成功。
- **限制：** 閘門未通過時不得建立正式 tag 或宣稱發布成功。授權不包含引入付費服務、代替使用者購買資源或未經同意傳送使用者資料。
- **依據：** 使用者明確表示擁有本專案完整控制權且發布亦已授權。
